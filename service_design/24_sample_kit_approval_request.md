# 24 実行キット雛形:承認依頼文

- 状態:仮案。第二対象業務(承認依頼文)用の再利用雛形。案件ごとに調整して使う。測定の主指標は時間ではなく**差し戻し・修正回数**。

## A. 入力テンプレート(依頼前に5分で埋めるメモ)

```text
# 承認依頼メモ(箇条書きでOK)
■ 承認してほしいこと(一文で):
■ いつまでに(期限と理由):
■ 費用・工数:
■ 背景(なぜ今これが必要か・2行以内):
■ 選択肢:A案__/B案__/推し案と理由:
■ リスクと対策:
■ 承認者が気にしそうな点と回答:
  (過去の差し戻し理由リストから選ぶ→F参照)
```

## B. プロンプト(1本目:依頼文生成)

```text
あなたは意思決定の速い上司に向けた社内文書の編集者です。
以下のメモを、下のフォーマットに沿った承認依頼文に整えてください。

制約:
- 依頼事項と期限を冒頭に置く
- メモにない情報を追加・推測しない(不足は【要確認】と書く)
- 承認者が YES/NO を判断できる材料(費用・リスク・代替案)を漏らさない
- 全体で500字以内、敬体

# メモ
(Aの内容を貼る)

# 出力フォーマット
(Cの内容を貼る)
```

## C. 出力テンプレート

```text
【承認のお願い】____の件(期限:__/__)
1. ご承認いただきたいこと:(一文)
2. 費用・工数:
3. 背景:(2行以内)
4. 案の比較:A案__/B案__ → 推奨:__(理由)
5. リスクと対策:
6. ご懸念になりそうな点:(想定質問→回答)
※お忙しければ 1と2のみで判断可能です。
```

## D. 確認チェックリスト(送信前・5項目)

- [ ] 冒頭の一文だけで「何を求められているか」が分かるか
- [ ] 金額・期限・数字は根拠資料と一致しているか
- [ ] 承認者の過去の差し戻し理由(F)に先回りできているか
- [ ] 記号化した固有名詞を戻したか
- [ ] 長すぎないか(500字超なら削る。詳細は添付・リンクへ)

## E. 使用上の注意

`23` E と同じ(AI入力禁止情報・最終責任・型の見直し条件)。

## F. 承認者プロファイル(初回ヒアリングで作成・このキットの心臓部)

```text
# 承認者の確認観点メモ(ヒアリングで顧客と作る)
- 承認者が必ず聞くこと(例:費用対効果/他部門への影響/前例):
- 過去の差し戻し理由(実例2〜3件):
- 承認が速かった依頼の特徴:
- NGワード・地雷(あれば):
```

※この観点メモが入力テンプレ(A)の「承認者が気にしそうな点」の選択肢になる。**差し戻しの主因が「承認基準がそもそも存在しない」だった場合は⑤組織問題であり、キットでは解決しない**(`15`の中止判定へ)。
