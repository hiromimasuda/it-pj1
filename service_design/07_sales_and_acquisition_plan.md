# 07 販売・集客設計(Phase 7)

- 状態:仮案(承認待ち)。初期顧客は広告ではなく知人・紹介から獲得する前提。
- 提案文の本文は `18_customer_message_templates.md`、一枚説明は `13_one_page_service_offer.md`。

## 1. 候補者選定条件(誰に声をかけるか)

必須条件(全て満たす):
- Hiromiが直接連絡できる、または紹介者を介して連絡できる
- 従業員10〜150名企業の実務を持つ責任者・マネージャー(候補A)、または PC定型業務を持つ個人事業主(候補B)
- 毎週または毎月くり返すPC業務を持っていそうである
- 小さな支出を自分で判断できる立場

避ける相手:
- 現職(Legaseed)の顧客・取引先・利害関係者(公私分離。会社経由の関係を私用サービスに流用しない)
- 断りにくい力関係にある相手(需要の誤認につながる)
- AIの一般論を聞きたいだけの人

## 2. 候補者リストの評価軸

リストは**リポジトリに置かない**(実名を含むため。ローカルまたは私用メモで管理し、リポジトリには匿名化した集計のみ記録する)。

| 評価軸 | 高評価の目安(各1〜3点) |
|---|---|
| 課題の具体性 | 業務名と「時間がかかる」を本人が口にしたことがある |
| 支払い意思 | 自己投資・ツール課金の実績が見える |
| 意思決定権 | 9,800円を誰にも聞かず払える |
| 実行余力 | 14日以内に対象業務を2回以上行う時期にいる |
| 情報共有可能性 | 画面共有・匿名化に応じられそう |
| 紹介可能性 | 同属性の知人・コミュニティを持つ |

運用:候補20名をリストアップ→スコア上位から候補A3名・候補B3名を選定→残りは第2陣として保持。

## 3. 個別提案文(3種類)

`18_customer_message_templates.md` に本文を用意。共通原則:
- AIを主語にしない(D-002)。「業務がひとつ楽になる」を主語にする
- 「興味ある?」で終わらせず、**対象業務を一つ挙げてもらう**質問で締める
- 一枚説明は返信があってから送る(最初から添付しない=売り込み感の回避)

| 種類 | トーン | 締めの行動要求 |
|---|---|---|
| 親しい知人向け | 率直・短文・モニターであることを開示 | 「毎週やってる面倒な業務、ひとつ思い当たる?」 |
| 仕事関係者向け | 丁寧・実績と限定数を明示 | 対象業務の有無と15分の適合確認の打診 |
| 紹介経由向け | 紹介者への言及から開始・信頼の借用 | 一枚説明送付の許可取り |

## 4. 一枚説明の構成(本文=`13`)

誰向けか→扱う業務→Before/Afterイメージ(架空例と明記)→提供の流れ→受け取るもの→顧客の所要時間→料金→情報の取り扱い→対象外→申込み方法。

## 5. 予約・支払いを確認する方法(行動測定)

「興味があります」は成果として数えない。記録する行動は以下のみ:

| 行動 | 記録内容 |
|---|---|
| 対象業務の具体提示 | 業務名・頻度・所要時間を本人が言えたか |
| 日程予約 | 提案から予約までの日数 |
| 料金支払い | 支払日・自腹/経費の別(H10) |
| 実業務の画面共有 | 同意したか・社内許可が要ったか |
| 二回目の自力利用 | 実施日(H5) |
| 紹介・次業務依頼 | 実際の連絡・依頼が発生したか(H8) |

集計は `10_validation_plan_7days.md` の判定に直結させる。支払い手段(銀行振込/PayPay等)は運用開始前にHiromiが決定(承認事項)。
