# 23 実行キット雛形:週次報告

- 状態:仮案。第一対象業務(週次報告)用の再利用雛形。案件ごとに顧客の実業務へ合わせて調整して使う(そのまま渡さない)。工程10(キット作成90分)の短縮が目的。
- キット点数の調整:AI初心者→プロンプト1本のみ+テンプレ2点/AI中級以上→チェック用プロンプト追加可(`25`学び2)。

## A. 入力テンプレート(顧客が報告前に5分で埋めるメモ)

```text
# 週次報告メモ(所要5分・箇条書きでOK)
■ 今週の結論(一言):順調/注意/要相談
■ 主要な数字:【指標1】__(先週比__)/【指標2】__(先週比__)
■ 完了したこと(最大3つ):
■ 進行中・来週やること(最大3つ):
■ 問題と対応(問題→自分の対応→残る懸念):
■ 上司に判断・支援してほしいこと(なければ「なし」):
```

※固有名詞(顧客名・候補者名等)は【A社】【候補者A】のように記号化して書く。

## B. プロンプト(1本目:下書き生成)

```text
あなたは簡潔な社内報告の編集者です。以下の箇条書きメモを、
下の出力フォーマットに沿った週次報告に整えてください。

制約:
- メモにない情報を追加・推測しない(不明な箇所は【要確認】と書く)
- 結論を最初に書く
- 全体で400字以内
- 敬体(です・ます)

# メモ
(ここにAの内容を貼る)

# 出力フォーマット
(ここにCの内容を貼る)
```

## C. 出力テンプレート(報告フォーマット)

```text
【週次報告】____週(担当:____)
1. 結論:(順調/注意/要相談+一言)
2. 数字:(指標と先週比)
3. 今週の完了:(最大3行)
4. 来週の予定:(最大3行)
5. 問題と対応:(問題→対応→残る懸念)
6. ご依頼事項:(判断・支援してほしいこと。なければ「なし」)
```

※受け手(上司)が最初に見る項目をヒアリングで確認し、順序を入れ替える。

## D. 確認チェックリスト(提出前・5項目)

- [ ] 数字は転記元と一致しているか(AIは数字を検算しない)
- [ ] 記号化した固有名詞を実名に戻したか/戻してはいけない場所はないか
- [ ] 「ご依頼事項」は相手が YES/NO で答えられる形か
- [ ] 先週の報告と矛盾していないか(前週分を横に開いて確認)
- [ ] AIが【要確認】と書いた箇所を埋めたか

## E. 使用上の注意

- AIに入力しない:会社名・個人名・顧客/候補者の実名・未公開の数値実績(記号化すれば可)
- AI出力の内容の最終責任は利用者本人にある(本サービスはAI出力の正確性を保証しない)
- この型が合わなくなったら(受け手交代・報告形式変更)、無理に使い続けず見直す

## F. 調整メモ(Hiromi用・案件ごと)

- ヒアリングで確認して差し替える箇所:①受け手が最初に見る項目 ②主要指標2つ ③記号化ルール ④報告の提出先ツール(Slack/メール/Docs)
- 転記作業が主因の場合、このキットの前に「転記の廃止・統合」(改善順序1〜2)を先に設計する(`25` SAMPLE-02)
