## 2. 推奨(仮決定・検証前提)

### 第一対象候補:週次報告(週次の定期報告業務)

選定理由:
1. **頻度が最も確実。** 週1発生なら14日で必ず2回以上実行でき、検証B(初回テスト→一週間以内の二回目自力利用→Before/After測定)がそのまま成立する唯一性が高い。
2. **入力→出力の構造が定型的**で、テンプレート化・AI初稿生成との適合が高い(改善検討順序の1〜6だけでも削減余地が見つけやすい)。
3. **顧客の自覚が強い**(「毎週の報告に時間がかかる」は本人が言語化しやすい課題)。
4. 数値・固有名詞の匿名化がしやすく、情報管理リスクが相対的に低い。
5. SAMPLE-02(採用責任者の週次報告)で設計テストが可能。

### 第二対象候補:承認依頼文

選定理由:
1. **課題の強さ(差し戻し・修正回数)が9候補中で最も鋭い。** 測定指標が「時間」でなく「修正回数・差し戻し回数」になり、価値が伝わりやすい。
2. 週1前後の頻度で14日検証が成立する。
3. Hiromiの社内調整・承認プロセスの経験と最も適合する。
4. SAMPLE-01(マーケ責任者の承認依頼)で設計テストが可能。
5. リスク:承認者(上司)の基準という顧客本人の外側に原因がある場合、AI・テンプレでは解けない(対象外問題への切り分けがヒアリングで必須)。

### 顧客が別の業務を提示した場合

第一・第二はあくまで「こちらから提案する際の想定」。実顧客が適合条件(週次以上・30分以上・14日で2回以上・匿名化可能)を満たす別の企画・承認・報告業務を提示した場合は、その業務を優先する。

## 3. 対象外業務(初期3件では扱わない)

| 業務 | 除外理由 |
|---|---|
| 月次報告 | 14日以内に2回実行できず、検証Bの「二回目自力利用」を測定できない。**業務としての適合は高いため、検証期間の設計を変えた後の有力候補** |
| 企画書初稿 | 頻度不足+個別性が高くテンプレ再利用性の検証に不向き。単価が高く正式商品化後の候補 |
| 稟議前論点整理 | 判断比重が大きくAI適合が低い。承認依頼文の付随作業として一部カバー |
| 会議資料 | 会議ごとに型が異なり、一業務限定の原則から逸脱しやすい(範囲膨張リスク) |
| 振り返り資料・関係者説明文 | 発生タイミングが読めず14日検証が組めない |
| 進捗報告 | 単体では課題が弱い。週次報告に含まれる場合はその一部として扱う |

## 4. 未確認事項

1. 実顧客の週次報告・承認依頼の実所要時間・修正回数(表の値はサンプルと推論)
2. 「差し戻しが減る」ことへの支払い意思が「時間が減る」より強いか
3. 候補B(個人事業主)に対する読み替え:週次報告→顧客向け定期報告、承認依頼文→顧客向け提案・確認依頼文。この読み替えで同一の実行キット構造が保てるか
4. 週次報告の改善が20%以上(検証B成功基準)に届くか — 元が30分程度の場合、絶対削減量が小さく価値が伝わらないリスク
5. 対象業務を2つ提示した場合に顧客が選べるか、混乱するか(一枚説明の設計に影響)
